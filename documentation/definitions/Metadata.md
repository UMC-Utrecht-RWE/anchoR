> The study-variable specification: one row per `variable_id x window_name`, describing which concept to look for, where the window sits relative to the anchor, and how to collapse matches.

Metadata is the "recipe" table anchoR cross-joins against [Population](Population.md). Each row says: for this `variable_id`, look for `concept_id` inside a window built by a [Constructor](Constructor.md) (named in the `constructor` column), and collapse whatever [concept](Concepts.md) records land in that window using a [Selector](Selector.md).

Mandatory columns after normalisation: `variable_id`, `concept_id`, `window_name`, `constructor`, `selector`, `start_offset`/`end_offset`, `anchor_start_col`/`anchor_end_col` (aliased from `anchor_date_start`/`anchor_date_end`), `range_min`/`range_max`, and the six episode-window columns `anchor_start_offset`/`anchor_end_offset`, `before_start_episode_offset`/`after_start_episode_offset`, `before_end_episode_offset`/`after_end_episode_offset` (used only by the episode-based constructors see [Episode-Based Window Engine](<Episode-Based Window Engine.md>)). `normalize_metadata()` fills in sensible defaults (`NA_real_`) for anything not supplied, so a minimal metadata table only needs `variable_id`, `concept_id`, `constructor`, `selector`, and `start_offset`/`end_offset`.
