> [Engine](<Episode-Based Window Engine.md>) configured with `episode_select = "CURRENT"`: window(s) built from the one episode containing the anchor date, if any.

Selects the single episode where `start_episode <= anchor <= end_episode` (using the row's `anchor_start_col` value, `T0` by default, as the anchor, via [classify_episodes()](<Episode-Based Window Engine.md>)). A person whose anchor date doesn't fall inside any episode produces no window and thus no result for that variable.

That one episode's window(s) come from the border-offset formula in [Episode-Based Window Engine](<Episode-Based Window Engine.md>): `before_start_episode_offset`/`after_start_episode_offset` relative to `start_episode`, `before_end_episode_offset`/`after_end_episode_offset` relative to `end_episode`. Whether a set outer side (`before_start_episode_offset`/`after_end_episode_offset`) combines the two pairs into one shared window, or a set inner side (`after_start_episode_offset`/`before_end_episode_offset`) with no outer side anywhere makes each pair its own region, is the full rule on that page — read it before relying on anything beyond the two common shapes below.

Two common shapes:
- **Anytime during the current episode**: leave all four border offsets `NA_real_` (neither pair set → the unshifted episode span becomes the window).
- **Since the start of the current episode, up to the anchor**: this constructor alone always windows relative to the *episode's own* `start_episode`/`end_episode`, never the anchor directly — use `IN_CURRENT_PREG` together with a `GENERIC` variable anchored at `T0` if you need "up to today" rather than "up to the episode's end."

If a border-offset window overshoots the episode's own real bounds (a common risk when a pair is full — the formula doesn't know how long the episode actually is), `cap_start_to_episode`/`cap_end_to_episode` (both `NA`/unset by default) pull it back in — see "Step 3" in [Episode-Based Window Engine](<Episode-Based Window Engine.md>).

`anchor_start_offset`/`anchor_end_offset` are also read by this constructor, but for a different purpose than the border offsets above: they don't shape the window, they clip it. See "Step 4" in [Episode-Based Window Engine](<Episode-Based Window Engine.md>) — after the border-offset formula (and any episode-bounds capping) builds a window, `anchor_start_offset`/`anchor_end_offset` (when not `NA`) enforce a hard `[anchor_start_col + anchor_start_offset, anchor_end_col + anchor_end_offset]` boundary that window must fall inside; a window entirely outside it comes out invalid. Leave both `NA` (the default) if you don't want a hard anchor-relative boundary at all.
