> [Engine](<Episode-Based Window Engine.md>) configured with `episode_select = "PRIOR"`: one or more windows, one per episode classified `"prior"`.

Selects *every* episode `classify_episodes()` labels `"prior"` (see [Episode-Based Window Engine](<Episode-Based Window Engine.md>) for the exact rule: relative to the current episode's own start if one exists, otherwise relative to the anchor directly), not just the most recent one. A person with several prior episodes gets one candidate [Window](Window.md) per prior episode (or two, if that episode's border offsets produce two regions see below); the [Selector](Selector.md) then picks across all of them together (e.g. `LATEST` returns the latest matching record from *any* of those windows).

Each selected episode's window(s) are computed independently, from its own `start_episode`/`end_episode` and the row's four border offsets, using the same formula as [IN_CURRENT_PREG](IN_CURRENT_PREG.md) see [Episode-Based Window Engine](<Episode-Based Window Engine.md>) for the full border-offset rule and worked examples. Because every selected episode in one metadata row shares the same offsets, there's no way to give one prior episode a different clamp than another within a single `in_prior_pregnancy` variable.

A person with **no current episode** still gets prior episodes: unlike the current-episode-relative case, the anchor-relative fallback in `classify_episodes()` means "ended before the anchor" is enough on its own.
